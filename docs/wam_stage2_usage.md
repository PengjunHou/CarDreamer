# Using the Stage-2 UWM: inference / closed-loop compare / online BS

Three ways to *use* the trained Stage-2 Unified World Model (`WAMUnifiedWorldModel`), built on top of its
existing inference modes (`propose_policies`, `rollout_future_bev`, `inverse_policy_search`). 设计→代码：

## Shared building blocks (`stage2.py`, exported from `toolkit/wam`)
- `load_wam_uwm(ckpt, device)` — rebuild the UWM from a Stage-2 checkpoint (configs are saved in the ckpt).
- `decode_chunk_to_wampolicy(chunk, candidate_ids, *, num_formats, step=0, sel_threshold=0.5)` — turn a
  generated `[H,M,P]` policy chunk into an interpretable `WAMPolicy` (slot `m` → `candidate_ids[m]`;
  `σ(sel)>thr` selected; modality = argmax format; bw = clamped scalar). Uses `decode_policy_vector`.

## Phase 1 — inference verification (CARLA-free)
`scripts/eval_wam_stage2_inference.py` on recorded flow samples:
- `propose_policies` vs recorded GT chunk → slot-level **selection-match %** + per-slot L2.
- `rollout_future_bev` (GT policy) → `decode_bev` → **IoU / recon loss** vs `bev_future`, against a
  copy-last-history baseline.
- Recorded samples don't store candidate ids → policies checked at member-slot level (not named).
```bash
python scripts/eval_wam_stage2_inference.py \
  --checkpoint outputs/wam_stage2_multi/stage2_step2000.pt --data-dir data/wam_flow_multi --limit 300
```
First finding (3-scene / 2203-sample model): selection-match ≈ 77%; **future-BEV IoU ≈ 0.45 < copy-last
baseline ≈ 0.69** → the BEV-generation half is under-trained (needs more data); the policy half is OK.

## Phase 2 — closed-loop comparison (generator vs enumerated, live scene)
`scripts/record_wam_graph_timeline.py --counterfactual --cf-uwm-checkpoint <uwm>` adds a `stage2` policy
(generated by `_cf_stage2_policy`: build C^BS from `sim._wam_graph` + notable → `propose_policies` →
`decode_chunk_to_wampolicy`) into the counterfactual set, scored by the **same Stage-1 `_cf_uncertainty`**
as `ego_only / nearest_single / all_candidates`. So one timeline directly compares the generator's policy
to the enumerated ones on U^π (0-latency).
```bash
python scripts/record_wam_graph_timeline.py --task carla_group_right_turn_auto --carla-port 2000 \
  --steps 300 --seed 0 --counterfactual --cf-policies ego_only,nearest_single,all_candidates \
  --cf-uwm-checkpoint outputs/wam_stage2_multi/stage2_step2000.pt \
  --out outputs/cf_stage2/cf_timeline.jsonl -- \
  --env.wam.predictor_mode=checkpoint --env.wam.predictor_checkpoint=outputs/wam_stage1/stage1_step1000.pt
# then visualize with --compare-policies ego_only,single_nearest,all_candidates,stage2
```

## Phase 3 — online BS integration (`policy_sampler_mode=stage2`)
`v2v_comm_mixin.py`: new sampler mode where the BS proposes the policy from the UWM each Td.
- `_load_wam_uwm()` (cached), config `env.wam.uwm_checkpoint`, `env.wam.uwm_candidates`.
- `_install_policy` → `_sample_stage2_comm_policy`: build C^BS from `_wam_graph` + notable →
  `propose_policies(k)` → `decode_chunk_to_wampolicy` → `_wampolicy_to_commpolicy` → `proc.set_policy`.
```bash
# live run:
--env.wam.policy_sampler_mode=stage2 --env.wam.uwm_checkpoint=outputs/wam_stage2_multi/stage2_step2000.pt
```

## Simplifications / not done
- Phase 3 picks the **first** proposed candidate; hybrid "propose k → Stage-1 U^π picks lowest" is a
  future refinement (needs a Stage-1 model loaded alongside in the env).
- Phase 2 uses the 0-latency counterfactual path (not comm-replay) for the generator comparison.
- C^BS uses a single request-vehicle graph (per the Stage-2 v1 simplification).
- BEV-generation half is weak (Phase-1 IoU < baseline) → more/diverse data + training needed.
